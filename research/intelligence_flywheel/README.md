# Intelligence, hyperdeflation, and a household-benefit flywheel

This packet tests a strengthened but narrower Alignment Theorem claim.  A
Moore-like capability path can support an alignment margin only through an
explicit causal bridge: verified task capability must reduce relevant unit
costs, savings must reach an accessible household basket, protected benefits
must be funded, and the resulting reward must outrun the benefit of deviation.

The exact boundary remains

\[
  B_t < M_t K_t,
\]

where `B` is policy-relative deviation benefit, `M` is real purchasing-power
multiplier, and `K` is protected ethical participation/benefit.  Intelligence
is not any of those variables by definition.

## What was executed

- An exact Python model compares direct doubling, compute-power, logistic,
  DAC-reinvestment, incomplete-pass-through, and rebound maps.
- Lean 4.33.0 proves a geometric crossing theorem, a constructive fixed-
  deviation doubling witness, bounded-reward impossibility, strict-boundary
  rejection, and the nine-fact DAC gate implications.
- A complete 512-row Tau packet accepts only the all-true row.
- The packet executed correctly on the source-pinned local Tau candidate.  The
  candidate is not the reviewed `c4926740...` binary and cannot promote the
  reviewed replay.
- A sender-scoped Tau Testnet `o5` rule executed through the native ABI at
  Testnet revision `9f9240...`: all true allowed, each single false blocked,
  missing custom evidence blocked, and a different sender remained unaffected.

## What the result means

The positive result is conditional mechanism mathematics, not a prediction.
If a full automation/transmission bridge makes purchasing power grow faster
than deviation benefit, a strict crossing epoch follows.  The negative results
are equally important: partial pass-through creates a price floor, logistic
saturation bounds the multiplier, rebound can cancel the price decline, and a
zero-return DAC does not compound.

Tau is necessary for this rule *on the current Tau Net protocol path* because
that path executes Tau specifications as its policy arbiters.  Tau's decidable,
executable specifications and revision model are a particularly direct fit for
policy-as-code.  This packet does not prove that no other formal platform could
implement an analogous architecture.
